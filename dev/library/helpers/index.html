Helper utilities

RxGPs exports several utility functions used throughout the message passing rules and by end users.

Mean function application

RxGPs.apply_mean_fn — Function
apply_mean_fn(x, mf)

The mean function mf at the input x, a number or a vector of numbers. A 1-vector is unwrapped, so a mean function of one input can be written for a number: with mf(x) = x^2, apply_mean_fn(3, mf) == apply_mean_fn([3], mf) == 9. A longer vector is passed whole. For several inputs, broadcast: apply_mean_fn.(Xu, mf).

source

Applies the scalar mean function mf to an input x. Handles dispatch for PointMass, Distribution, scalar, and vector inputs.

Mean and covariance extraction

RxGPs.mean_cov_scalar_matrix — Function
mean_cov_scalar_matrix(x)

Return (mean, cov) where mean is a scalar and cov is a 1×1 matrix. Input x must be one-dimensional (scalar, length-1 vector, PointMass, or univariate distribution).

source
RxGPs.mean_cov_vector_matrix — Function
mean_cov_vector_matrix(x)

Return (mean, cov) where mean is a vector and cov is a matrix, regardless of the dimensionality of x. Accepts Real, AbstractVector, PointMass, or any NormalDistributionsFamily.

source

These convenience functions extract (mean, cov) from various input types (PointMass, Real, distribution) and normalise the output shapes:

FunctionReturns
mean_cov_scalar_matrix(scalar, 1×1 matrix)
mean_cov_vector_matrix(vector, matrix)

Linear algebra helpers

RxGPs.jdotavx — Function
jdotavx(a, b)

The sum of the products of the elements of a and b, of the same length, vectorised with LoopVectorization's @turbo: dot(a, b) for real arrays of any shape.

source
RxGPs.create_blockmatrix — Function
create_blockmatrix(A, d, M)

The (dM)×(dM) matrix A as a d×d matrix of views of its M×M blocks: block (i, j) is A[(i-1)M+1:iM, (j-1)M+1:jM]. MultiSGP uses it for the second moment of its stacked inducing variables.

source

Hyperparameter optimisation

The kernel hyperparameters $\theta$ are learned outside message passing, by an M-step that alternates with inference: the functions below compute the negative log of the backward messages towards $\theta$, summed over the data, and its gradient, for a gradient-based optimiser such as Flux.jl's, as in the usage examples, or Optim.jl.

RxGPs.neg_log_backwardmess_fast — Function
neg_log_backwardmess_fast(θ; y_data = nothing, x_y_data, ω_data = nothing, x_ω_data, q_v,
                          q_w = nothing, q_Wg = nothing, method = nothing, kernel, mean_fn, Xu,
                          Lm_fn = nothing, Kxx_fn = nothing, Kxu_fn = nothing) -> Real

The negative log of the backward messages towards the kernel hyperparameters θ of the univariate VSGP nodes, summed over the data, computed directly rather than through the rules: the M-step objective of grad_llh_default!.

Function-value observations (UniSGP) and operator observations, such as gradients (UniSGP_dID), are both supported, alone or together; an input may be a value, a PointMass or a distribution.

$K_{uu}(\theta)$ is factorised with the package's K_uu jitter, as in the rules.

Keywords

  • y_data, x_y_data: function values and their inputs, or nothing. x_y_data is required even without values; pass nothing.
  • ω_data, x_ω_data: operator observations (vectors of length P) and their inputs, or nothing; x_ω_data is required likewise.
  • q_v: the marginal of the inducing variables v.
  • q_w: the noise precision of the function values (a GammaShapeRate or PointMass), needed with y_data.
  • q_Wg: the noise precision of the operator observations, needed with ω_data.
  • method: the approximation method for distributional inputs, such as ghcubature(21).
  • kernel: the kernel constructor θ -> k.
  • mean_fn: the prior mean function.
  • Xu: the inducing inputs.
  • Lm_fn, Kxx_fn, Kxu_fn: the operator functions of a UniSGPMeta, needed with ω_data.
source
RxGPs.neg_log_backwardmess_uncertain — Function
neg_log_backwardmess_uncertain(θ; y_data, qx, v, Uv, w, kernel, Xu, method) -> Real

The negative log of the backward messages towards θ of UniSGP nodes with a zero mean function whose inputs are distributions, summed over the data.

Keywords

  • y_data: the observed function values.
  • qx: the inputs' distributions.
  • v: the mean of the inducing variables.
  • Uv: the upper Cholesky factor of their second moment, $\Sigma_v + \mu_v \mu_v^\top$.
  • w: the mean of the noise precision.
  • kernel, Xu: the kernel constructor θ -> k and the inducing inputs.
  • method: the approximation method for the kernel expectations, such as ghcubature(21).
source
RxGPs.neg_log_backwardmess_msg — Function
neg_log_backwardmess_msg(θ; in_data_, out_data_, q_v, q_W_, meta_) -> Real

The negative log of the messages towards θ of a set of UniSGP_dID nodes, at θ: the M-step objective for observations grouped in batches, each batch with its own noise precision and meta, as when function values and gradients are observed with different operators.

Each message is the node's own rule towards θ, so the objective is exactly what message passing sends to θ.

Keywords

  • in_data_: a vector of batches; batch i is a vector of inputs, each a value, a PointMass or a distribution.
  • out_data_: the matching batches of observations or their marginals.
  • q_v: the marginal of the inducing variables v.
  • q_W_: the noise precision of each batch, a PointMass or a Wishart.
  • meta_: the UniSGPMeta of each batch.

See also grad_llh_msg!.

source
RxGPs.grad_llh_default! — Function
grad_llh_default!(grad, θ; kwargs...) -> grad

Write into grad the gradient, by ForwardDiff, of neg_log_backwardmess_fast at θ; it takes the same keywords. This is the M-step of the README's EM loop: an optimiser such as Flux's then updates θ with grad.

source
RxGPs.grad_llh_msg! — Function
grad_llh_msg!(grad, θ; in_data_, out_data_, q_v, q_W_, meta_, frozen_indices = nothing) -> grad

Write into grad the gradient, by ForwardDiff, of neg_log_backwardmess_msg at θ, which takes the same keywords. The entries of frozen_indices are set to zero, so that a gradient step leaves those hyperparameters where they are.

source
RxGPs.neg_log_backwardmess_multi — Function
neg_log_backwardmess_multi(θ; y_data, qx, sumRv_Wbar, v, W, tr_W, kernel, Xu, method) -> Real

The negative log of the backward messages towards θ of MultiSGP nodes (coregionalisation $C = I$), summed over the data.

Keywords

  • y_data: the observed output vectors, of dimension D.
  • qx: the inputs' distributions.
  • v: the mean of the stacked inducing variables, of length D·M.
  • W, tr_W: the mean of the noise precision and its trace.
  • sumRv_Wbar: $\sum_{ij} W_{ij} R_{v,ij}$, the M×M blocks of the second moment of v weighted by W, precomputed once.
  • kernel, Xu, method: the kernel constructor θ -> k, the M inducing inputs and the approximation method for the kernel expectations.
source

grad_llh_multi(θ; kwargs...) -> Vector
